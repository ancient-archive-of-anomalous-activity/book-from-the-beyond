Note: For code and ID3, the three letter code is based on information about the object, enetity, or location, whilst the ID# is the actual unique permanently desginated number for whatever is being documented. The three letter code is changable and not unique, and exists to tell us quick information about what is being described on that particular file on record.

Here's how it works:

The first letter, which must be O, E, or L, tells us the type of phenomenon being recorded, namely, if it is an Object, Entity, or a Location.

The second letter, which must be K, C, or R, tells us the containment class of the object being recorded and described. The three containment classes are Kill, Contain or Cage, and Ritual or Release. Maybe there should be a fourth letter, Unknown, Uncontained, Unleashed, though that would be more of a status rather than a containment order or prescription.

The third letter, which must be X, V, or Z, tells us the threat level of the phenomena in question. For levels 0-5, the correct letter is Z. For levels 5-10, use V. For levels greater than 10, put Z.

The file number is not the same as this number nor does it have anything to do with it's three letter code. It does incorporate the numberical ID. THe file number is recorded according to the following blueprint:

File No. #(Site#-YYY#-ID#)

Where Site# is the number of the site where the file is being recorded, YYY# is the last three digits of the year the phenomenon was first recorded, and ID# is the unique ID of the phenomenon being recorded.
